# Pixel Arcade

Dashboard di retrogaming per la console: backend Python (solo libreria standard) e frontend React servito dal backend.

## Requisiti

- Console: Python 3.8 o superiore, Google Chrome o Chromium.
- PC di sviluppo: Node 20 e npm 10.

## Build del frontend

Dal PC, nella cartella montata:

```bash
cd dashboard/frontend
npm ci
npm run lint
npm run test
npm run build
```

La build finisce in `dashboard/frontend/dist/`, che il backend serve così com'è.

**Loghi delle console (facoltativi).** I loghi mostrati nella scheda TUTTE e nelle Impostazioni non stanno nella repo. Prima della build li scarica da Wikimedia Commons lo script:

```bash
python3 dashboard/tools/fetch_logos.py
```

I PNG finiscono in `dashboard/frontend/public/logos/` (esclusa dal `.gitignore`), che la build copia in `dist/logos/`; accanto, `index.json` riporta file, fonte, licenza e autore di ogni logo. I loghi sono marchi dei rispettivi proprietari. Ai sistemi che su Commons non hanno un logo lo script dà l'icona del tema «Systematic» di RetroArch (CC BY 4.0 nella copia di libretro, MIT per l'autore BAXY), copiata dagli asset di RetroArch installati sulla macchina (`--assets CARTELLA` per indicarli): per questo conviene lanciarlo sulla console. `--force` scarica di nuovo anche quelli già presenti, `--out CARTELLA` cambia la destinazione. Senza loghi né icone la dashboard mostra il nome della console.

## Avvio sulla console

```bash
cd ~/retrogames
bash run_dashboard.sh
```

Il servizio ascolta su `http://127.0.0.1:8765` e apre Chrome a schermo intero (finestra app, senza barre né schede) con un profilo dedicato.
Il clic destro apre il normale menu di Chrome; F11 esce e rientra nello schermo intero.
Ctrl+C nel terminale ferma il servizio e chiude quel Chrome.
Chiudendo la finestra di Chrome della dashboard si ferma anche il servizio (e l'eventuale partita); anche chiudere il terminale equivale a Ctrl+C. Se all'avvio è ancora aperto un Chrome con il profilo della dashboard (`chrome-profile/`), il servizio lo chiude prima di aprirne uno nuovo.
Dalla dashboard: START+SELECT tenuti 3 s (oppure Ctrl+Q e conferma) chiudono Chrome e il servizio, se non c'è una partita in corso.
START+SELECT premuti e rilasciati entro 1 s scollegano invece tutti i giocatori e riportano a «PRESS START»; rilasciati tra 1 e 3 s non fanno nulla.

Dopo 1 minuto senza comandi (Impostazioni → Aspetto: 30 secondi, 1, 2, 5, 10 minuti o «Mai»), fuori dalle partite, la dashboard fa lo stesso: escono tutti i profili e torna «PRESS START», così chi arriva dopo sceglie di nuovo il suo. Il salvaschermo continua a partire con la sua attesa, anche sopra «PRESS START»; se parte prima, i profili escono sotto di lui. Mentre un'estensione ha il controllo dei comandi il salvaschermo non parte e la dashboard resta dov'è: escono solo i profili.

Opzioni (passate a `python3 -m pixelarcade`):

| Opzione | Effetto |
| --- | --- |
| `--port N` | Porta HTTP locale (predefinita 8765) |
| `--no-browser` | Avvia solo il servizio, senza Chrome |
| `--data-dir DIR` | Cartella del database e del profilo Chrome (predefinita `~/.config/pixel-arcade`) |
| `--base DIR` | Cartella da cui partono i percorsi relativi delle impostazioni, come `games` (predefinita: quella che contiene `dashboard/`) |

Controllo rapido: `curl http://127.0.0.1:8765/api/health`.

Su GNOME, mentre la finestra della dashboard è aperta, i riquadri delle notifiche del desktop (per esempio gli aggiornamenti disponibili) sono spenti, come con «Non disturbare» (`gsettings org.gnome.desktop.notifications show-banners`); alla chiusura tornano accesi. Le notifiche arrivate nel frattempo restano nell'elenco di GNOME. Se «Non disturbare» era già attivo, la dashboard non lo tocca. Il file `notifications-banners` nella cartella dei dati indica che le notifiche le ha spente la dashboard: se si chiude male, le riaccende alla chiusura successiva. Con `--no-browser`, o senza GNOME, le notifiche non cambiano.

### Processore al massimo

Durante le partite la dashboard può mettere il governor di cpufreq su `performance` e, a fine partita, rimettere quello di prima (Impostazioni → Configurazioni → Prestazioni). Il governor si cambia solo da root: lo fa lo script `system/pixelarcade-cpu`, che accetta solo i nomi dei governor, e la dashboard lo lancia con `sudo -n`. Si installa una volta, con la password:

```bash
cd ~/retrogames/dashboard
sudo install -o root -g root -m 755 system/pixelarcade-cpu /usr/local/sbin/pixelarcade-cpu
echo "$USER ALL=(root) NOPASSWD: /usr/local/sbin/pixelarcade-cpu" | sudo tee /etc/sudoers.d/pixelarcade-cpu
sudo chmod 440 /etc/sudoers.d/pixelarcade-cpu
sudo visudo -c
```

Il governor in uso prima della partita si annota in `cpu-governor` nella cartella dei dati: se la dashboard si chiude a metà partita, si rimette al suo avvio successivo. Se all'inizio della partita il governor è già `performance` (messo a mano), la dashboard non lo tocca.

## Libreria e comandi

Ogni sottocartella di `games/` è una console. La repo porta già, vuote, le cartelle di tutte le console e i computer riconosciuti (circa 90, dai core di RetroArch: `PRESETS` e `FOLDERS` in `backend/pixelarcade/systems.py`), e all'avvio la dashboard crea quelle che mancano nella cartella dei giochi: basta mettere i file nella cartella giusta. Restano fuori motori di gioco e giochi singoli (DOOM, Quake, ScummVM…), varianti della stessa console e calcolatrici.
Una console senza giochi è spenta per tutti: non compare nella riga delle schede finché non la si accende nelle Impostazioni o con la casella in TUTTE; quando riceve i giochi si accende da sola, se nessuno l'ha spenta. Il nome mostrato è quello della cartella in maiuscolo, con `_`, `-`, `.` ecc. al posto degli spazi; i colori si calcolano da quel nome.
Le cartelle riconosciute (`backend/pixelarcade/systems.py`, con alias come `megadrive`, `ps1`) hanno estensioni e citazione dedicate.
I giochi si leggono all'avvio e restano in memoria: dopo aver aggiunto file o cartelle, usa «Aggiorna libreria» nelle Impostazioni.

Joypad, tastiera e mouse danno gli stessi comandi. Per ora sono attivi:

| Joypad | Tastiera | Mouse / tocco | Azione |
| --- | --- | --- | --- |
| Croce o stick | Frecce | Passaggio sul gioco; rotellina sulla griglia | Sposta la selezione |
| A (✕ sui joypad PlayStation) | Invio o Spazio | Clic su «Gioca» | Sulla griglia porta alle azioni del gioco (Gioca, Descrizione, Trofei, Altro); su «Gioca» avvia, su «Altro» apre il menu con Core, Comandi, Configura e Playlist |
| LB / RB | `[` / `]` | Clic sulla scheda | Console precedente / successiva |
| LT / RT | PagSu / PagGiù | Clic su una lettera della striscia `# A–Z` | Iniziale precedente / successiva |
| X | `/` o Ctrl+F | Clic su «Cerca» nella barra comandi | Apre la ricerca con la tastiera a schermo |
| Y | `P` | Clic su «Preferito» nella barra comandi | Aggiunge o toglie il gioco dai preferiti del giocatore di quel joypad (tastiera e mouse: P1), al rilascio del tasto |
| Y tenuto 0,8 s | `R` (o `P` tenuto) | Clic su «Cosa gioco?» nella barra comandi | Apre «Cosa gioco?»: un gioco a caso della griglia (solo P1) |
| B | Esc o Backspace | Clic su «Griglia» nella barra comandi; tasto laterale «indietro» del mouse | Dalle azioni del gioco torna alla griglia; con una ricerca attiva, la cancella (l'intestazione della griglia lo ricorda) |
| START | F2 | Clic su uno slot P1/P2 in alto | Entra come giocatore o riapre «Chi gioca?» (cambio profilo, Esci) |
| SELECT | F3 | Clic su «Profilo» / «Impostazioni» nella barra comandi | Apre la pagina profilo del giocatore di quel joypad (tastiera e mouse: P1); senza giocatori apre le Impostazioni (al rilascio del tasto) |
| START+SELECT rilasciati entro 1 s | — | — | Scollega tutti i giocatori e torna a «PRESS START» |
| START+SELECT tenuti 3 s | Ctrl+Q, poi conferma | — | Chiude Chrome e il servizio |

SELECT e START agiscono al rilascio, così si possono premere insieme per la chiusura senza aprire altro.

**Navigazione circolare.** Ovunque (griglia, iniziali con LT/RT, azioni del gioco, Impostazioni, profilo, «Chi gioca?», menu, tastiera a schermo) una pressione oltre il bordo riparte dall'altro capo: da # con ← si va all'ultimo gioco, dal primo campo con ↑ all'ultimo.
Nella griglia ↑ e ↓ passano alla prima o all'ultima riga nella stessa colonna (se manca, all'ultimo gioco).
Una direzione tenuta premuta e la rotellina si fermano invece al bordo: per ripartire dall'altro capo si rilascia e si preme di nuovo.

**Riga delle console e scheda TUTTE.** Le schede in alto seguono l'ordine delle marche, alfabetico: Arcade, Atari, Bandai, Computer, NEC, Nintendo, Sega, SNK, Sony e per ultime le console di «Altro». Dentro una marca le console sono in ordine di uscita (`BRANDS` in `backend/pixelarcade/systems.py`). In coda vengono le schede delle estensioni, tra cui TUTTE e TOURNAMENT.
TUTTE mostra ogni console, anche quelle fuori dalla riga, divise per marca: le frecce scelgono la marca, A ci entra (le altre si attenuano), poi le frecce scelgono la console.

| Joypad | Tastiera | Azione |
| --- | --- | --- |
| A | Invio | Tra le marche entra nella marca; su una console la apre |
| X | `/` | Accende o spegne la casella della console nella riga del profilo di P1 |
| Y | `P` | Rende la console la preferita del profilo di P1; sulla preferita la toglie |
| B | Esc | Torna alle marche |

La casella accanto al nome è verde con la spunta se la console è nella riga, vuota se non c'è.
- Senza scelte del profilo valgono le Impostazioni (Console → interruttore «Accesa / Spenta»): le console accese sono già spuntate.
- Una casella cambiata dal profilo resta così anche quando le Impostazioni cambiano: una console accesa dal profilo resta nella sua riga anche se poi viene spenta per tutti. Le console mai toccate seguono le Impostazioni.
- La console preferita ha il cuore rosso ed è sempre nella riga: la sua casella ha il lucchetto e X non la toglie.
- Senza profilo (ospite o nessun giocatore) la riga è quella delle Impostazioni: le caselle hanno il lucchetto, X e Y mostrano un avviso.

Le scelte stanno nel database (`POST /api/consoles/settings` e `POST /api/consoles/row`, vedi API.md). Una console aperta da TUTTE, o fuori dalla riga, torna a TUTTE con B dalla griglia; LB e RB partono da TUTTE.

**Giocatori.** Un joypad comanda la dashboard solo dopo aver premuto START: il primo che lo preme diventa P1, il secondo P2 (un terzo riceve «Due giocatori già attivi»).
Ognuno sceglie il proprio profilo nella sua finestra «Chi gioca?» (P1 a sinistra, P2 a destra), ne crea uno nuovo o gioca come ospite. In cima ci sono «Gioca come ospite» (già selezionato) e «Crea un nuovo profilo», sotto i profili: chi non ha un profilo suo entra come ospite invece di usare quello di un altro.
Se il joypad che entra non ha ancora un autoconfig di RetroArch, prima di «Chi gioca?» la stessa finestra apre «Configura il joypad» per quel giocatore (vedi «Joypad nei giochi» nelle Impostazioni). «Più tardi», Esc o la ✕ la saltano, e non viene richiesta di nuovo finché la pagina resta aperta.
La libreria risponde al joypad di P1; il joypad di P2 comanda la propria finestra e usa Y (preferiti) e SELECT (profilo).
Se P1 esce, P2 diventa P1. Tastiera e mouse funzionano sempre, anche senza giocatori, e con F2 o il clic su uno slot fanno entrare senza joypad.
I profili stanno nel database; nome da 1 a 25 caratteri (maiuscolo, spazi → `_`), unico.
Il joypad comanda la dashboard solo quando la finestra di Chrome è in primo piano: i tasti premuti in RetroArch non arrivano alla libreria.

**Preferiti e profilo.** Y salva il gioco selezionato nei preferiti del giocatore (sotto «Gioca» il cuore con P1 o P2, sulla copertina un pallino rosso P1 o azzurro P2); i preferiti si cambiano solo con Y; per un ospite vale solo finché resta nello slot.
Ogni partita di almeno 20 s dà XP e tempo ai profili in gioco (1 XP al minuto fino a 180, +5 per la partita, +25 per un gioco nuovo; sul gioco della sfida della settimana i minuti valgono il doppio): al rientro compare «+N XP» e, se si sale di livello, «Livello N · Titolo».
SELECT apre la pagina profilo: livello, ore di gioco, giochi provati, preferiti (A porta al gioco nella libreria, Y o il cuore lo tolgono), le ultime 5 partite e le preferenze.
Le preferenze si salvano subito: nome e colore (solo per un profilo registrato; il nome si scrive con la tastiera a schermo e non può essere quello di un altro profilo), console preferita (vedi «Riga delle console e scheda TUTTE»: nel profilo di P1 la voce «Scegli in TUTTE» apre la scheda sulla sua marca; un profilo nuovo nasce senza; la libreria ci passa quando P1 entra), generi, difficoltà (solo indicativa), Filtro CRT di P1 (righe di scansione sulla dashboard e, se `paths.crt_shader` è impostato, shader in RetroArch), Vibrazione joypad (impulso breve all'avvio e sui preferiti, se il joypad la supporta; in RetroArch `input_rumble_gain`).
La sezione «Salvataggi» elenca i giochi con un «Riprendi» del profilo, con miniatura e data; A porta al gioco nella libreria.
Dalla pagina profilo si raggiungono anche «Cambia profilo», «Esci» e le Impostazioni.

**Cosa gioco?** Y tenuto (o `R`) nella libreria pesca un gioco a caso tra quelli della griglia: console selezionata, filtri e ricerca attivi, senza i ⊘ incompatibili. Le copertine scorrono come in una slot machine e rallentano fino al gioco scelto (con la riduzione del movimento del sistema compare subito). A ferma il giro; poi ◀ ▶ scelgono tra «Vai al gioco», «Ancora» e «Chiudi» (anche col mouse) e A preme quello evidenziato. X ripesca e B chiude anche direttamente. Un tocco breve di Y resta il preferito, che ora scatta al rilascio. Nel pannello «Filtri» restano anche «Sorprendimi» e «Sorprendimi da tutte le console».

**Classifica di casa.** Quando una sola finestra «Chi gioca?» è aperta, nella metà libera dello schermo compare la classifica: con START di P1 (finestra a sinistra) a destra, con START di P2 (finestra a destra) a sinistra; con entrambe le finestre aperte, sul telefono e sugli schermi verticali non si vede. Accanto alla classifica la finestra si stringe come quando sono due, così non si sovrappongono; tutte e due sono centrate in verticale tra l'intestazione e la barra comandi, con almeno 20 unità di margine da entrambe, e la classifica scorre se non sta nell'altezza.
- **Navigazione**: nella scelta del profilo → (P1) o ← (P2) portano il joypad nella classifica, che si accende nel colore del giocatore; ↑↓ scorrono persone e file di giochi, ← → passano tra le card di una fila; la direzione verso la finestra, quando da quella parte non c'è un'altra card, torna alla finestra anche dalla scheda di una persona, che resta aperta accanto (al rientro si riprende da lì); B dalla scheda torna alla classifica, dalla classifica alla finestra. Col mouse basta il clic; un clic nella finestra la riprende.
- **Persone**: A (o il clic) apre la scheda della persona al posto della classifica: in alto una fascia nel colore del profilo con avatar, livello e barra degli XP («340 / 500 XP»), poi quattro riquadri (ore, giochi, partite, punti RA con il rank), il pulsante per entrare, una barra divisa con le ore per console e tre file di card che scorrono di lato, fino a 10 ciascuna con 4 visibili e un quarto della successiva (più giocati con la durata, ultime partite con la data, preferiti con la console, scritte sulla copertina). «Gioca come NOME» entra con quel profilo nello slot della finestra (non c'è se il profilo è dell'altro giocatore). B torna alla classifica.
- **Giochi**: i giochi sono card con la copertina. A (o il clic) su una card (sfida, più giocati di casa, giochi della scheda di una persona) o sul gioco del vincitore della settimana prima lo prenota e torna alla finestra, dove una fascia ricorda «Poi si va a: …» (X o «Togli» la tolgono). Appena il giocatore entra (profilo, ospite, profilo nuovo o «Gioca come») la libreria va su «Gioca» di quel gioco; chiudendo la finestra la prenotazione si perde.
- I primi cinque profili per XP (a parità, per ore): coppa d'oro, d'argento e di bronzo ai primi tre, il numero al quarto e al quinto; a destra gli XP, sotto il nome livello e titolo, ore, punti RetroAchievements (hardcore più softcore, se il profilo è collegato e il sito risponde) e il gioco più giocato per tempo.
- **Sfida della settimana**: un gioco estratto a caso il lunedì (ora locale) tra quelli già giocati da almeno un profilo e ancora nella libreria, lo stesso fino a domenica anche se nel frattempo si giocano giochi nuovi. Vince chi ci gioca più tempo nella settimana; si vedono i primi tre, i giorni che mancano e chi ha vinto la settimana prima. I minuti giocati sul gioco della sfida valgono il doppio degli XP («Sfida della settimana ×2» nel riepilogo di fine partita). Finché nessun profilo ha giocato una partita la sfida non c'è.
- **I più giocati di casa**: i tre giochi con più tempo di tutti i profili insieme.

**Salvaschermo.** Dopo 2 minuti senza comandi (Impostazioni → Aspetto: 10, 15 o 30 secondi, 1, 2, 5, 10 minuti o «Mai») nella libreria, nel profilo o su «PRESS START», senza finestre aperte né partite in corso, compaiono a turno copertine a caso, preferiti dei profili e miniature dei «Riprendi», sopra il tema grafico: da due a quattro alla volta (due sugli schermi più alti che larghi), in punti a caso di tutto lo schermo e grandi il più possibile, senza sovrapporsi (si provano più disposizioni e vince quella che copre più schermo). Ogni immagine si muove piano in una direzione sua e a una velocità sua, senza mai toccare le altre. Conta solo la pressione di un tasto: un tasto o una levetta rimasti tenuti non lo tengono spento. Il primo tasto premuto, un clic o il mouse mosso lo chiudono, e quel tasto non fa altro (nemmeno al rilascio).

**Partite nel salvaschermo.** Durante le partite normali del P1 registrato la dashboard registra un solo pezzo di circa 45 secondi, dopo un minuto e mezzo di gioco (non nelle sfide trofeo, nelle prove dei core e su PS2, PSP e arcade): ogni registrazione salva uno stato e rallenta il gioco per un attimo, quindi una per partita. Non registra se il gioco ha già uno spezzone, né se il salvaschermo non li rigioca (contenuto «Copertine» o attesa «Mai»). A fine partita, se è durata almeno 3 minuti, il pezzo diventa lo spezzone, con il trofeo se ne è stato sbloccato uno mentre si registrava. **Tornei nel salvaschermo.** Se c'è un torneo di oggi (iscrizioni aperte con l'inizio oggi, in corso, oppure concluso oggi) e «Pubblicità dei tornei» è accesa, il salvaschermo mostra solo il suo manifesto a tutto schermo, senza copertine né spezzoni: dietro la copertina sfocata che si ingrandisce piano; da un lato la copertina nitida con il bordo dorato e sotto lo stato di partenza («SI PARTE DA QUI»), larghi uguali; dall'altro nome della serie, «Nª EDIZIONE — titolo», gioco e console e, secondo il momento, ora d'inizio con il conto alla rovescia ai secondi, oppure «IN CORSO» con i due avatar del prossimo incontro, il turno e quanti incontri mancano, oppure «CONCLUSO OGGI» con il podio; sotto gli iscritti con avatar (l'immagine del profilo, se c'è) e nome, i posti liberi tratteggiati e, a torneo in corso, testa di serie ed eliminati in grigio; poi premi e formato e, in fondo, la fascia «PREMI START E ISCRIVITI» («…E SEGUI IL TORNEO» a torneo in corso). Con più tornei di oggi i manifesti si alternano ogni 30 secondi; contro il burn-in tutto si sposta piano e ogni 3 minuti immagini e testi si scambiano di lato. Le misure seguono lo schermo, anche in 4:3; su uno schermo più alto che largo le immagini stanno sopra e i testi sotto. START chiude il salvaschermo e apre la scheda TOURNAMENT su quel torneo; gli altri tasti lo chiudono come sempre.

Restano gli ultimi 5 spezzoni di tutta la casa, di qualsiasi profilo: al sesto si cancella il più vecchio. Con il contenuto «Misto» (predefinito, Impostazioni → Aspetto) il salvaschermo, ogni 2 minuti di copertine, rigioca in RetroArch uno spezzone (a turno, a partire da quello mostrato meno di recente), senza audio, con la scritta «nome · gioco · data» in basso; con «Partite» rigioca solo spezzoni, uno dopo l'altro (copertine solo se non ce ne sono); con «Copertine» non li rigioca. Un tasto del joypad chiude spezzone e salvaschermo; chiudere RetroArch (per esempio con Esc) chiude anche il salvaschermo.

**Suoni.** La dashboard ha effetti chiptune (spostamento, conferma, indietro, cambio console, preferito aggiunto o tolto, «PRESS START», avvio di un gioco, errore, rullo di «Cosa gioco?», «LVL UP!» e trofei di fine partita) e una musica di sottofondo: un brano per la schermata iniziale, uno per ogni console (cambia poco dopo essersi fermati su una scheda) e uno per il Wrapped. Tutto è sintetizzato nel browser (`frontend/src/lib/sound.js`), senza file audio. La musica sfuma all'avvio di un gioco e riprende al ritorno; durante le partite non suona niente. Suoni e volumi sono in Impostazioni → Aspetto. Chrome parte con `--autoplay-policy=no-user-gesture-required`, perché i tasti del joypad non sbloccano l'audio; senza quel flag i suoni partono dopo il primo tasto della tastiera o clic.

**Wrapped.** A fine mese, e a fine anno, ogni profilo con almeno 3 partite nel periodo ha il suo Wrapped: schermate animate con tempo giocato, gioco e console preferiti, classifica dei giochi, trofei RetroAchievements, abitudini (giorno e fascia preferiti, giorni di fila, partita più lunga), rivale (il profilo con cui ha giocato più spesso, oppure quello con gli XP più vicini) e personaggio (Il Maratoneta, Il Collezionista di trofei, Mordi e fuggi, Il Fedele, L'Esploratore). C'è anche il Wrapped di casa, con tutte le partite dei profili, la classifica dei giocatori, la coppia che ha giocato più spesso insieme e il personaggio di ognuno. I periodi seguono l'ora locale; una partita conta nel periodo in cui è finita.
- Quando un profilo entra come P1 e il suo Wrapped più recente non è ancora stato visto, nella libreria compare «È pronto il tuo Wrapped»: «Guarda» lo apre, «Più tardi» (anche B) lo ripropone al prossimo ingresso. Il più recente è quello del mese appena chiuso; a gennaio è quello dell'anno.
- Quando entra P2 con P1 già dentro compare l'avviso del Wrapped di casa, sempre dopo quello personale. Finché non è stato visto, la schermata «PRESS START» lo ricorda in alto.
- Un Wrapped vale come visto quando si apre; quello di casa vale per tutti.
- Tutti i Wrapped restano nella scheda «Wrapped» del profilo e, quelli di casa, in Impostazioni → Aspetto.

**Sfida trofeo.** Chi sblocca un trofeo RetroAchievements può sfidare tutta la casa a sbloccarlo più in fretta, ripartendo da circa 5 minuti prima.
- Durante la partita, a ogni trofeo del P1 (profilo con l'account RetroAchievements collegato) la dashboard mette da parte lo stato periodico più vicino a 5 minuti di gioco prima dello sblocco; con meno di 5 minuti di gioco prende il più vecchio. Senza stati periodici prima del trofeo (o con gli stati periodici spenti) il trofeo non si può sfidare. Il tempo del creatore è il tempo di gioco dallo stato al trofeo, senza le pause del menu.
- A fine partita, dopo la modale «Fine partita», compare «Sfida tutta la casa» con i trofei della partita: si spuntano quelli da sfidare e «Lancia le sfide» le crea; «Non sfidare» (anche B) cancella tutti gli stati messi da parte, e così una nuova partita.
- Una sfida dura 15 giorni ed è aperta a tutti i profili, anche a chi ha già il trofeo e al creatore, che può migliorare il proprio tempo. Quando un profilo entra come P1 compare l'avviso delle sfide nuove di altri («Gioca» o «Più tardi», che lo ripropone al prossimo ingresso); senza account RetroAchievements l'avviso invita a collegarlo dal profilo (Trofei → «Collega account»). Gli avvisi delle sfide e del Wrapped non compaiono mai insieme.
- La sfida parte dallo stato, sempre con il core con cui è stato fatto e con la modalità Encore di RetroArch (`cheevos_start_active`): anche i trofei già sbloccati scattano di nuovo. Il tempo parte quando lo stato è caricato. La partita di una sfida non tocca «Riprendi», salvataggio interno e stati di soccorso del gioco. Conta solo il P1.
- A fine partita la modale dice com'è andata: nuovo record, miglior tempo personale, trofeo senza record o tentativo non riuscito. Ogni tentativo resta nella classifica della sfida (miglior tempo di ognuno e numero di tentativi).
- La scheda «Sfide» del profilo ha le sfide da giocare, quelle lanciate dal profilo (con «Migliora il tempo») e quelle concluse a cui ha partecipato. Alla scadenza lo stato si cancella e chi ha partecipato riceve il riepilogo con la classifica.
- Non si possono sfidare i trofei dei core che non salvano gli stati (MAME 2000).
- Nelle schermate ◀ ▶ (o il clic a sinistra e a destra) scorrono, A va avanti e sull'ultima chiude, B chiude.

**Torneo.** Tornei dal vivo tra i profili della casa, uno contro uno. Si preparano in Impostazioni → Torneo: le bozze e i tornei con le iscrizioni aperte possono essere quanti si vuole, in corso ce ne sarà uno solo alla volta.
- Ogni torneo è un'edizione di una serie (per esempio «GameNight Tournament», 1ª edizione, 2ª edizione…). La scheda elenca le serie; «＋ Nuova serie» la crea il P1 entrato col suo profilo, insieme alla 1ª edizione in bozza, salvata a ogni modifica. Tutti vedono i tornei, ma ognuno lo modifica solo chi l'ha creato.
- A apre la finestra della serie: a sinistra nome e descrizione della serie, le edizioni (dalla più recente) ed «Elimina serie»; a destra le classifiche, che LB/RB cambiano; in alto «＋ Nuova edizione». A su un'edizione apre il suo modulo (o la sola lettura, se è conclusa o annullata); B torna indietro.
- «＋ Nuova edizione» si usa quando nessuna edizione della serie è in bozza, in iscrizione o in corso: nasce una bozza che copia la più recente non annullata (gioco, stato di partenza, formato, regole, premi, partecipanti massimi e descrizione), senza titolo dell'edizione, data e iscritti. Il numero si dà alla creazione: il più alto tra le edizioni non annullate più uno. Un'edizione annullata resta nello storico come «Annullata», senza numero, che passa alla successiva; un'edizione eliminata lascia il buco nei numeri. Eliminando l'ultima edizione si elimina anche la serie; «Elimina serie» toglie tutte le edizioni (non con un'edizione in corso). I premi già dati restano.
- Classifiche della serie, sulle edizioni concluse, con chi ne ha giocata almeno una: **Medagliere** (ori, argenti, bronzi; a pari merito incontri vinti, poi edizioni giocate), **Punti** (10 al 1°, 7 al 2°, 5 al 3°, 3 al 4°, 2 al 5°, 1 di partecipazione agli altri, ritirati compresi; i pari merito di un piazzamento prendono tutti i punti del posto; a pari merito ori, poi incontri vinti) e **Incontri** (incontri vinti, il pareggio del girone vale mezzo, esclusi bye e vittorie a tavolino; a pari merito percentuale di vittorie, poi edizioni giocate). Se è tutto uguale la posizione è condivisa. Sotto c'è l'albo d'oro, con il vincitore di ogni edizione conclusa.
- Campi della serie: nome (obbligatorio) e descrizione. Campi dell'edizione: titolo facoltativo (per esempio «Japan version»: a schermo «GameNight Tournament · 2ª edizione — Japan version»), descrizione, data e ora d'inizio (facoltative), gioco di qualsiasi console, salvataggio di partenza, partecipanti massimi (anche nessun limite), formato, menu dei salvataggi bloccato durante gli incontri, lati P1/P2, premi (XP e titolo sul profilo) e combinazione dell'admin.
- Il salvataggio di partenza si registra giocando, col creatore come P1: «da zero» (dall'inizio, senza salvataggio interno), «con i miei dati» (dall'inizio con il salvataggio interno del creatore, per esempio con i personaggi sbloccati) o «da un mio slot» (dallo stato di uno slot del creatore). Si arriva al punto giusto (conviene poco prima della scelta della modalità o dei personaggi) e si esce: lo stato all'uscita e il salvataggio interno della sessione diventano del torneo, con il core della partita. «Riprendi» e salvataggio interno del profilo non cambiano. Con un core che non salva gli stati (MAME 2000) il torneo parte dall'inizio. «Nessuno, dall'inizio» toglie lo stato; cambiando gioco, stato e salvataggio interno del torneo si tolgono.
- Il formato si sceglie in una finestra a parte, dalla riga «Formato» del modulo, che ne mostra il riepilogo (per esempio «Eliminazione diretta · turni 1, semifinale come i turni, finale 3, 3° posto»). A sinistra ci sono i formati: eliminazione diretta, doppia eliminazione, girone all'italiana, svizzero e due fasi; per ora si scelgono l'eliminazione diretta, la doppia eliminazione e il girone all'italiana, gli altri sono grigi con «in arrivo». A destra ci sono solo le opzioni del formato. Teste di serie e lato vantaggiato non dipendono dal formato e sono righe del modulo: «Teste di serie» (a caso, per XP, per tempo giocato a quel gioco o misto) sotto «Formato», con «Pesi delle teste di serie» (XP e tempo a passi del 10%, predefiniti 50/50) solo col misto; «Lato vantaggiato» (nessuno, P1 o P2: la testa di serie migliore parte nell'altro lato) sotto «Lati P1 / P2», che con i lati liberi non si usa. Nella schermata «Avvia» la stessa finestra mostra tutto: opzioni del formato, teste di serie, pesi e lato vantaggiato. Per l'eliminazione diretta: partite per serie dei turni, della semifinale (anche «come i turni») e della finale, e finale per il 3° posto. Per la doppia eliminazione: serie dei turni, delle finali dei due tabelloni e gran finale con rivincita (predefinita: si rigioca solo se vince chi arriva dai perdenti), a incontro unico o nessuna, con la sua serie («come le finali», 1, 3 o 5; non c'è con «Nessuna»); il 3° posto non si sceglie, è chi perde la finale dei perdenti. Per il girone all'italiana: solo andata o andata e ritorno (al ritorno i lati si invertono), pareggi ammessi (no di predefinito), serie degli incontri (al meglio di 1, 3 o 5; con i pareggi un numero fisso di partite: 1, 2 o 3, e accendendoli 5 diventa 3), punti per vittoria, pareggio e sconfitta (solo con i pareggi, predefiniti 3/1/0), registra il punteggio (no di predefinito) e, con il punteggio, il punteggio a tavolino (vincitore e perdente, predefinito 1–0). Gli incontri del girone sono n(n−1)/2, il doppio con il ritorno, più gli eventuali spareggi. Cambiando formato le serie dei turni e della finale restano (nel girone con i pareggi la serie passa alla più vicina ammessa). Gli incontri della doppia sono 2n−2, più la rivincita se si gioca (per esempio «18–19» con 10 iscritti), 2n−3 senza gran finale. ▲ ▼ scelgono, ▶ passa alle opzioni, ◀ ▶ cambiano il valore, START salva tutto insieme; B torna ai formati e, dai formati, chiude senza cambiare nulla.
- Quando l'admin chiude le iscrizioni, la conferma dice quanti incontri si giocheranno con gli iscritti di quel momento: nell'eliminazione diretta uno in meno degli iscritti, più la finale per il 3° posto da 4 iscritti in su.
- La combinazione dell'admin è una sola per la serie e vale per tutte le edizioni. È una sequenza di tasti di qualsiasi lunghezza: START la conferma, SELECT ricomincia. Se c'è, serve per ogni modifica (compreso «Gestisci»), oltre al profilo del creatore; senza combinazione basta il profilo. A schermo si vedono solo i pallini, e nel database c'è solo un'impronta.
- «Pubblica» (servono il nome della serie e il gioco) apre le iscrizioni. Una bozza si elimina senza combinazione; un torneo pubblicato si annulla con la combinazione e va nello storico. Finché le iscrizioni sono aperte si cambia tutto; a torneo in corso solo i testi (nome e descrizione della serie, titolo e descrizione dell'edizione).
- Con almeno un torneo con le iscrizioni aperte o in corso compare in fondo alle console la scheda TOURNAMENT (le bozze no), con un pallino rosso se un torneo è in corso. Sulla scheda c'è un'anteprima: L1/R1, START e SELECT funzionano come sulle altre console, A entra. Dentro, con più tornei, a sinistra c'è l'elenco (◀ ▶ cambiano torneo) e a destra il dettaglio; con uno solo c'è il dettaglio a tutta larghezza. Il dettaglio ha in alto, come il manifesto del salvaschermo, copertina e stato di partenza («SI PARTE DA QUI») a sinistra, larghi uguali, e a destra nome della serie con «Nª EDIZIONE — titolo», gioco, data con conto alla rovescia, descrizioni della serie e dell'edizione, admin e formato, premi (o podio); sotto, a tutta larghezza, iscritti e posti, e in fondo le classifiche della serie con l'albo d'oro (L1/R1 cambiano classifica). ▲ ▼ fanno scorrere il dettaglio. A apre il menu del giocatore che l'ha premuto, P1 o P2 col proprio joypad; la prima voce, per chiunque, è «Allenati a <gioco>», che porta al gioco nella libreria per allenarsi con una partita normale. Lo stesso fa △ dal dettaglio, in ogni stato del torneo (a torneo in corso A apre il tabellone). B torna alla scheda.
- Nel menu un profilo si iscrive o si ritira finché le iscrizioni sono aperte e ci sono posti; ci si può iscrivere a più tornei. Un ospite trova «Crea un profilo per iscriverti». Il creatore, entrato come P1, vede anche le azioni dell'admin: «Iscrivi un profilo…», «Togli un iscritto…» (la combinazione si chiede una volta all'apertura dell'elenco), «Chiudi le iscrizioni» e «Riapri le iscrizioni». Con le iscrizioni chiuse nessuno si iscrive o si ritira da solo, ma il torneo resta sulla scheda. I partecipanti massimi non scendono sotto gli iscritti.
- «Avvia il torneo…» è l'ultima azione dell'admin nel menu. Servono almeno 3 iscritti e nessun altro torneo in corso; poi la combinazione, se c'è. Si apre una schermata a tutta pagina in tre passi. 1 Formato: gli iscritti e i cinque formati col numero di incontri (quelli non pronti grigi «in arrivo»); il formato delle impostazioni è segnato e già scelto, Y apre le opzioni (la stessa finestra delle Impostazioni), A o START vanno avanti. 2 Teste di serie: l'ordine calcolato col metodo scelto, con accanto il valore usato (XP, tempo giocato a quel gioco senza le partite di torneo, o il punteggio del misto); A prende un giocatore, ▲ ▼ lo spostano, A lo lascia; X rimescola (a caso: un nuovo sorteggio); START va avanti. 3 Anteprima: il tabellone vero, con i bye alle teste di serie migliori e il primo incontro in alto; A segna un giocatore del primo turno e, su un altro, li scambia di casella (le teste di serie restano quelle del passo 2); START chiede «Avviare il torneo? Le iscrizioni si chiudono.». B torna al passo prima e, dal passo 1, chiude senza avviare. Le scelte si salvano a ogni cambiamento come bozza del torneo: se la schermata si chiude (B dal passo 1, uscita dei profili), rientrando con «Avvia il torneo…» e la combinazione si riparte dal passo e dalle scelte salvate, anche dopo un riavvio; se nel frattempo gli iscritti sono cambiati restano formato e opzioni e le teste di serie si rifanno. Al passo 1, con una bozza, X «Ricomincia da capo» torna alle impostazioni del torneo. La bozza si cancella all'avvio, all'annullamento e cambiando il formato nelle Impostazioni. Mentre la schermata è aperta i profili non escono da soli dopo i minuti senza comandi. Le scelte fatte qui (formato e opzioni) diventano quelle del torneo; il torneo passa «In corso» col pallino rosso, le iscrizioni si chiudono e in Impostazioni → Torneo si cambiano solo i testi della serie e dell'edizione.
- Con un torneo in corso l'anteprima della scheda mostra «Prossimo incontro» (i due giocatori con la testa di serie, il turno e la serie) o «In gioco ora» col pallino rosso, e «Incontro N di M» (senza i bye). Il torneo in corso è il primo dell'elenco: A su di esso apre il tabellone, e se è l'unico torneo A dalla scheda ci va direttamente. Il tabellone occupa tutta la larghezza sotto una fascia con titolo, gioco, formato e avanzamento: una colonna per turno unite da linee, il 3° posto sotto la finale («si gioca prima della finale»), schede con numero d'ordine, vincitore evidenziato e perdente attenuato, «Vincitore di Q2» per le caselle non decise, «passa il turno» nei bye, «PROSSIMO» col bordo oro, «IN GIOCO» in rosso, «TAVOLINO». Le schede restano a grandezza leggibile (diventano compatte solo oltre 32 posti nel primo turno) e il tabellone scorre in orizzontale e in verticale seguendo il cursore, lasciando attorno alla scheda selezionata un pezzo delle schede vicine e delle linee. La croce sposta il cursore (che parte dal prossimo incontro) tra gli incontri della colonna e tra i turni, senza fermarsi sui bye; una pressione oltre il bordo riparte dall'altro capo, il tasto tenuto si ferma. Con il 3° posto L1/R1 saltano tra il tabellone e il 3° posto, tornando sull'ultimo incontro selezionato in ciascuno; senza 3° posto non fanno nulla. Anche l'anteprima del passo 3 di «Avvia» scorre allo stesso modo. A apre il menu dell'incontro del giocatore che l'ha premuto, con «Partite» (partita, vincitore e lati; «Nessuna partita giocata» se non ce ne sono); Y apre «Info torneo» (il dettaglio, con gli iscritti per testa di serie e gli eliminati attenuati col turno in cui sono usciti; ▲ ▼ scorrono); B torna indietro di un livello: dal tabellone all'elenco o, con un solo torneo, alla scheda. Nel menu dell'incontro il creatore come P1 ha anche le azioni dell'admin; la combinazione, se c'è, si chiede alla scelta dell'azione. «Vittoria a tavolino…» (incontro con i due giocatori noti e non concluso, anche in gioco con partite già dichiarate, che restano): si sceglie chi vince, conferma «Vittoria a tavolino di <Nome>?», la scheda mostra «TAVOLINO» e il vincitore avanza. «Ritira un giocatore…» (i giocatori dell'incontro ancora in gara): perde a tavolino l'incontro in cui si trova, subito se l'avversario è noto, altrimenti da solo appena lo diventa; in «Info torneo» è «Ritirato». «Annulla il risultato» toglie un passo alla volta: l'ultima partita dichiarata di un incontro in gioco; il risultato di un incontro concluso (torna in gioco con una partita in meno, il vincitore esce dalla casella dopo), solo se l'incontro che ne dipende non è iniziato, altrimenti la voce è grigia con «l'incontro successivo è già iniziato»; un tavolino; un ritiro (il giocatore torna in gara). Nel girone all'italiana «Ritira un giocatore…» dà a tavolino agli avversari tutti gli incontri che gli restano («Ritirare Anna dal torneo? I suoi 3 incontri da giocare diventano vittorie a tavolino per gli avversari. I risultati giocati restano.»); in classifica resta al suo posto, attenuato. «Annulla il risultato» vale per qualsiasi incontro concluso, che torna da giocare nella sua giornata e diventa il Prossimo; su un tavolino del ritiro annulla il ritiro e riapre tutti i tavolini automatici, non quelli dati prima dall'admin. Nel calendario un tavolino mostra le vittorie necessarie a zero (con i pareggi la serie intera) o, con il punteggio registrato, il «Punteggio a tavolino». Le azioni sono rifiutate mentre una partita di quell'incontro è aperta sulla console. Sempre sotto «Admin» c'è «Annulla il torneo…»: conferma «Il torneo è in corso: annullare…? I risultati restano nello storico.», poi la combinazione se c'è; lo stesso testo compare annullando il torneo in corso da Impostazioni → Torneo. L'annullamento è rifiutato mentre una partita di un incontro è aperta sulla console (un incontro sospeso tra due partite non lo blocca); il torneo va nello storico come annullato, senza podio né premi.
- Nel girone all'italiana il passo 3 di «Avvia» ha a sinistra l'ordine dei giocatori nel calendario e a destra l'anteprima del calendario, divisa per giornate, con chi riposa. A segna un giocatore e, su un altro, li scambia di posto: il calendario si ricalcola, le teste di serie restano e decidono i lati. L1/R1 passano all'anteprima, dove ▲ ▼ scorrono gli incontri, e tornano ai giocatori; □ ripristina l'ordine delle teste di serie. Non si spostano i singoli incontri né le giornate.
- Nel girone all'italiana in corso il riquadro «Prossimo incontro» mostra «Giornata 3 di 7» (con «· Ritorno») e, se qualcuno non gioca in quella giornata, «Riposa: <nome>». Al posto del tabellone ci sono la classifica e il calendario affiancati. La classifica arriva dal backend (`standings`): posizione, giocatore, G, V, P, S, DP, +/− e PF, Pt (P e Pt solo con i pareggi, +/− e PF solo con il punteggio), medaglie ai primi tre da quando c'è un incontro concluso, «=» per chi è ancora pari dopo tutti i criteri e «SPAREGGIO» per i pari sul podio a girone finito; il ritirato resta al suo posto, attenuato, e non prende la medaglia. Sotto c'è il glossario delle sigle mostrate. Il calendario è diviso per giornate, con i risultati, chi riposa e le etichette PROSSIMO, IN GIOCO e TAVOLINO. L1/R1 passano dall'uno all'altro; all'ingresso il cursore è sul Prossimo, nel calendario. Nel calendario ▲ ▼ scorrono gli incontri, ◀ ▶ vanno al primo incontro della giornata prima o dopo, A apre il menu dell'incontro; nella classifica ▲ ▼ scorrono i giocatori e A apre «Incontri di <nome>» (risultati e incontri da giocare), dove A porta al calendario su quell'incontro. Y apre «Info torneo», B torna indietro.
- Spareggi del girone: quando l'ultimo incontro è concluso, chi è ancora pari dopo tutti i criteri per un posto del podio (1°–3°, contando solo chi non è ritirato) gioca uno spareggio; gli altri pari restano a pari merito con «=». Gli incontri compaiono subito in fondo al calendario, in una giornata «SPAREGGIO · 2° POSTO» per ogni gruppo, e partono quando qualcuno li avvia. Il riquadro e la fascia del tabellone mostrano «Serve uno spareggio per il 2° posto» e l'avanzamento «Spareggio · Incontro 1 di 3». Due pari giocano un incontro con la serie del girone che ha sempre un vincitore (niente PAREGGIO; con i pareggi la serie fissa diventa al meglio di un numero dispari: 2 → 3). Tre o più pari giocano un mini-girone di sola andata con le regole e i criteri del girone, calcolati solo sugli spareggi. Gli spareggi non cambiano i numeri della classifica ma, conclusi, ordinano i pari. Se dopo gli spareggi qualcuno è ancora pari sul podio, la classifica mostra «SORTEGGIO» e il messaggio «Sorteggio per il 2° posto: tocca all'admin». Nel menu di un incontro l'admin ha «Sorteggia il 2° posto…»: prima la conferma, poi la combinazione; l'ordine estratto compare in un elenco («2° · Sara», «3° · Anna»), A apre il podio e il torneo si conclude. Finché uno spareggio non è iniziato, annullare un risultato del girone lo cancella, e lo spareggio si ricrea a girone di nuovo finito; con uno spareggio iniziato o concluso la voce è grigia con «prima va annullato lo spareggio». Gli spareggi si annullano come gli incontri del girone. Alla fine i piazzamenti seguono la classifica (i pari fuori dal podio a pari merito); i ritirati vanno dopo tutti gli altri, senza podio né premio; premi, podio, archivio e profilo sono come negli altri formati.
- Nella doppia eliminazione il tabellone ha due righe, VINCENTI sopra e PERDENTI sotto, e a destra la gran finale con la rivincita. Gli incontri hanno un codice: V2-1 (vincenti, turno 2, primo incontro), P3-2 (perdenti), GF e GF2; le caselle non decise dicono «Vincitore di V1-2» o «Perdente di V2-1». Gli incontri dei perdenti senza avversario possibile non si disegnano. Il tabellone scorre su due assi: ◀ ▶ tra le colonne, ▲ ▼ tra gli incontri e tra le due righe; L1/R1 saltano tra vincenti, perdenti e gran finale, tornando sull'ultimo incontro selezionato in ciascuno. La rivincita si gioca solo se la gran finale la vince chi arriva dai perdenti («solo se vince <Nome>»), altrimenti resta «non giocata» e non conta; l'avanzamento dice per esempio «Incontro 12 di 18–19» finché non si sa. In «Info torneo» ogni iscritto ha dove si trova e le sconfitte («Vincenti · imbattuto», «Perdenti · 1 sconfitta»), chi è uscito il piazzamento della colonna dei perdenti in cui ha perso («Eliminato · Perdenti, turno 3 · 7°–8°»). Nel passo 3 di «Avvia» si possono anche scambiare gli incroci dei perdenti (□ ripristina quelli standard). Il ritiro manda fuori il giocatore senza incontri da chiudere a mano: nei vincenti perde a tavolino, scende nei perdenti e lì l'avversario vince da solo; nei perdenti è subito fuori; in gran finale vince l'altro, anche la rivincita se è aperta. In «Info torneo» è «Ritirato · Vincenti, turno 2» (dove si è ritirato) con il piazzamento della colonna dei perdenti in cui esce. «Annulla il risultato» richiede che non siano iniziati né l'incontro del vincitore né quello in cui è sceso il perdente; altrimenti la voce è grigia col codice («P2-1 è già iniziato»). I tavolini automatici collegati si riaprono; annullare la gran finale riporta la rivincita in attesa, ma non si può se la rivincita è iniziata.
- Sul prossimo incontro il menu ha in cima «Gioca l’incontro», per uno dei due giocatori (P1 o P2) o per il creatore come P1, senza combinazione. Si apre la schermata «Incontro»: i due giocatori grandi con avatar, testa di serie e lato (P1 a sinistra, P2 a destra), «Partita N · al meglio di K» e il modo dei lati. Con i lati alternati nella partita 1 la testa di serie migliore è nel lato svantaggiato (con «Nessuno» parte al P1), poi si scambiano; con i lati sorteggiati c'è una breve animazione del sorteggio; con i lati liberi ◀ ▶ scambiano i lati, ma solo al primo passo dell'assegnazione. Per tutto l'incontro P1 e P2 della dashboard sono i due giocatori secondo i lati, con i joypad di P1 e P2 di prima (a uno slot vuoto va il primo joypad collegato libero); B torna al tabellone e rimette i giocatori di prima. I joypad non si scambiano a mano: si assegnano ai lati nella schermata, con tre passi. «<P1> premi START»: il joypad che preme START diventa quello di P1. «<P2> premi START»: lo stesso con un altro joypad; SELECT, da qualsiasi joypad, torna al passo di P1. Prova dei tasti: sotto ogni giocatore un joypad disegnato (croce, quattro tasti frontali, dorsali, grilletti, SELECT e START, senza simboli di marca) accende il tasto premuto dal joypad di quel lato; START accende o spegne PRONTO, SELECT ANNULLA, e con tutti e due su ANNULLA si torna al passo di P1. Qui B del joypad si accende soltanto: il tabellone resta a Esc. Tastiera e mouse non assegnano; con meno di due joypad collegati la schermata lo dice. L'assegnazione vale solo in RetroArch e per tutto l'incontro: segue i giocatori quando i lati si scambiano, e dalla partita dopo si riparte dalla prova dei tasti; gli slot della dashboard tengono i loro joypad, così il creatore dichiara e governa sempre col suo. Se all'avvio un joypad assegnato non è più collegato si rifà l'assegnazione. Con tutti e due PRONTO la partita parte dallo stato del torneo, con una copia del suo salvataggio interno, trofei spenti; la partita dà XP e conta nelle statistiche come le altre (nella cronologia del profilo porta «TORNEO» con il titolo completo dell'edizione); l'incontro diventa «In gioco». Con i salvataggi bloccati il menu in gioco offre solo «Torna al gioco» ed «Esci»; senza blocco salva e carica in slot temporanei dell'incontro, mai in quelli dei profili. A fine partita si torna alla schermata «Incontro», senza la schermata degli XP.
- «Chi ha vinto la partita N?»: i due giocatori coi lati della partita e «Nessuno dei due: rigioca». Sotto ogni giocatore una riga sobria dice gli XP della partita appena giocata («+8 XP», con «· ▲ Livello N» se è salito di livello), al posto del riepilogo a modale delle partite normali. Dichiara il creatore, cioè il P1 di prima dell'incontro (col suo joypad o la tastiera): ◀ ▶ tra i due giocatori, ▼ «rigioca», A conferma, poi la combinazione se il torneo ce l'ha (sbagliata: non si registra nulla). «Rigioca» non conta la partita e si rigioca lo stesso numero. Ogni partita giocata si dichiara una volta sola; dopo un riavvio della dashboard la partita non dichiarata si rigioca. Poi la schermata della partita dopo coi lati aggiornati e il punteggio della serie, oppure, alle vittorie necessarie, «<Nome> vince l'incontro 2-1»: A torna al tabellone col cursore sul nuovo «Prossimo». Vincitore e perdente passano negli incontri che ne dipendono (i perdenti delle semifinali nell'incontro per il 3° posto, giocato prima della finale) e gli slot temporanei dell'incontro si cancellano.
- **Fine partita automatica** (estensione `autoresult`). Per i giochi che conosce (un file di regole per gioco in `backend/pixelarcade/addons/autoresult/rules/`, riconosciuto dall'hash RetroAchievements; per ora Windjammers) le impostazioni del torneo hanno la sezione FINE PARTITA AUTOMATICA: «Attiva» (sì per impostazione predefinita), «Tipo di conteggio» (Windjammers: «Vittoria della partita») e la spiegazione della regola. Durante gli incontri l'estensione legge la memoria del gioco; a fine partita aspetta 3,5 secondi, chiude il gioco e registra da sola vincitore e punteggio, senza «Chi ha vinto la partita N?» né combinazione: compare l'avviso «Partita 1: vince <nome>» e si passa alla partita dopo, oppure «<Nome> vince l'incontro». Un pari diventa pareggio nei tornei che lo ammettono, altrimenti la partita si rigioca. Se l'esito non si legge (partita chiusa prima della fine) si dichiara a mano come sempre, e un risultato sbagliato si corregge con «Annulla il risultato». A torneo in corso l'estensione si può solo spegnere (con la combinazione, se c'è), non riaccendere.
- Nel girone all'italiana con i pareggi ammessi in mezzo ai due giocatori c'è PAREGGIO (◀ ▶ lo raggiungono) e la serie è un numero fisso di partite («Partita 2 di 2», sotto i giocatori «1 vinta · 1 pari»): l'incontro si chiude all'ultima partita, vince chi ne ha vinte di più, altrimenti «Pareggio 1-1». Con «Registra il punteggio», dopo A compaiono due numeri sotto i giocatori (1–0 per chi vince, 0–0 con il pari): ▲ ▼ cambiano quello selezionato (0–99), ◀ ▶ passano all'altro, A conferma solo se è coerente (chi vince ha più punti, con il pari uguali), B torna alla scelta. A incontro chiuso c'è anche «Punteggio 7–5»; nel calendario, in «Incontri di <nome>» e nelle «Partite» compare il punteggio.
- La finale è l'ultimo incontro (l'incontro per il 3° posto si gioca prima): dopo «<Nome> vince l'incontro» della finale compare il podio, con la copertina del gioco sfocata dietro, il titolo del torneo e tre gradini (2° a sinistra, 1° al centro più alto, 3° a destra, con due giocatori se sono 3° a pari merito), avatar, nomi e gli XP del premio. A chiude e torna alla scheda TOURNAMENT. Piazzamenti: 1° e 2° dalla finale, 3° e 4° dall'incontro per il 3° posto oppure, senza, i due semifinalisti sconfitti 3° a pari merito; gli altri a pari merito per il turno in cui sono usciti (5°, 9°…), un ritirato col posto del turno del ritiro. Con «Premi» attivo 1°, 2° e 3° ricevono 100, 50 e 25 XP (25 a ciascun 3° a pari merito), che contano negli XP del profilo, nel livello e nel titolo; è l'unico XP che dà un torneo. Il torneo concluso resta sulla scheda per 3 giorni con «CONCLUSO» e il podio nell'anteprima; A apre il tabellone in sola lettura (il menu dell'incontro ha solo «Partite»). Poi la scheda sparisce, se non ci sono altri tornei con le iscrizioni aperte o in corso.
- Le edizioni concluse e annullate stanno nell'elenco della loro serie. A apre l'edizione in sola lettura: dati, podio (non per gli annullati) e tabellone. «Elimina dall'archivio» è del creatore come P1: conferma «Eliminare il torneo dall'archivio? I premi restano.», poi la combinazione se c'è. Gli XP del premio e le righe nella cronologia dei profili restano.
- Nel profilo, scheda «Statistiche», c'è la riga «Tornei: N giocati · N vinti · miglior piazzamento N°» (nascosta senza tornei conclusi) e nella cronologia, tra le partite, la riga del piazzamento «<Titolo>: 2° · +50 XP».
- A incontro iniziato B sulla schermata «Incontro» chiede «Sospendere l'incontro?»: l'incontro resta «In gioco» con le partite dichiarate (e la partita da dichiarare, se c'è) e si riprende con «Gioca l'incontro» dalla partita dopo. Gli slot temporanei si cancellano. «Partite» nel menu dell'incontro elenca le partite dichiarate con vincitore e lati.
- A ogni ingresso di un giocatore, se c'è un torneo con le iscrizioni aperte e posti liberi a cui non è iscritto, compare un avviso. Al profilo chiede «Ti vuoi iscrivere?» (con più tornei «Vuoi vederli?»): «Sì» apre la scheda sul torneo, con «Iscriviti» evidenziato, oppure sull'elenco. All'ospite dice «Crea un profilo se vuoi partecipare»: «Crea profilo» apre il modulo del nuovo profilo. Il profilo creato prende il posto dell'ospite e si va alla scheda come dopo «Sì».

Nella tastiera a schermo (la pagina «#+=» ha anche ° ª º e le vocali accentate, maiuscole con MAIUSC): A digita il tasto evidenziato, X cancella, Y aggiunge uno spazio, LB/RB spostano il cursore di un carattere a sinistra o a destra (anche tenuti), START conferma, B annulla e ripristina la ricerca precedente.
La tastiera fisica scrive direttamente (Backspace cancella, Home/Fine portano a inizio/fine, Invio conferma, Esc annulla) e i tasti a schermo si possono cliccare.
La ricerca filtra la console selezionata mentre si scrive: contano tutte le parole, senza distinguere maiuscole e accenti, nel titolo e nel nome del file.

## Avvio dei giochi

A avvia il gioco selezionato con RetroArch (`retroarch.command`, `--verbose --fullscreen -L core --appendconfig file gioco`).
Prima la schermata di avvio mostra per 2 secondi l'inserimento del gioco, in stile pixel art, e solo dopo parte la richiesta di avvio (`frontend/src/lib/insert.js`); B due volte in quei 2 secondi annulla senza avviare.
Ogni console ha la sua scena e il suo movimento, con la copertina sull'etichetta: nel NES, nel Disk System e nel PC Engine il supporto entra dallo sportello frontale; nello SNES, nel Mega Drive, nell'N64, negli Atari e nelle console d'epoca la cartuccia scende dall'alto e scatta l'interruttore; nelle portatili (Game Boy, GBA, Game Gear, PSP…) entra da dietro e lo schermo si accende con il titolo; nel DS la console si apre e la card sale nella fessura; nella PS1, nel Saturn e nel Dreamcast il disco passa dal coperchio; nella PS2, nel Mega CD e nel 3DO dal cassetto; negli arcade cade un gettone con «CREDIT 1». Ogni supporto ha il suo suono.
In fondo alla schermata i consigli scorrono ogni 4 secondi (`frontend/src/lib/tips.js`): uscita dal gioco, combinazione dei salvataggi, combinazione di emergenza e «Riprendi», con i tasti impostati.
Il file `--appendconfig` (`paths.appendconfig`) viene riscritto a ogni avvio con le chiavi presenti nel `retroarch.cfg` della console (quello nella cartella sopra `paths.cores`):
`input_quit_gamepad_combo` (l'uscita dal gioco scelta in Impostazioni → Joypad: `"7"`, START tenuto 2 secondi, predefinita; `"8"`, SELECT tenuto 2 secondi; `"4"`, START+SELECT), `quit_press_twice = "false"` (esce al primo colpo) e `config_save_on_exit = "false"` (RetroArch non salva questi valori nel suo `retroarch.cfg`).
Senza `input_quit_gamepad_combo` nel `retroarch.cfg` i giochi non partono e le Impostazioni mostrano un avviso.
L'uscita predefinita non è START+SELECT perché RetroArch passa i tasti anche al gioco: in molti giochi PS1 (per esempio Tekken 3) START+SELECT è il reset, e «Riprendi» ripartirebbe dal menu principale. START invece mette il gioco in pausa, e «Riprendi» riparte dalla pausa.
Con dei giocatori entrati, il file assegna anche il joypad di P1 al giocatore 1 di RetroArch e quello di P2 al giocatore 2 (`input_player1_joypad_index`, `input_player2_joypad_index`).

I tasti del joypad di P1 e P2 (A, B, X, Y, L, R, L2, R2, Start, Select, `input_player{1,2}_<tasto>_btn` e `_axis`) sono sempre scritti a `"nul"`: RetroArch usa quelli dell'autoconfig del joypad collegato, quindi un `retroarch.cfg` con tasti sbagliati non conta. Croce, L3, R3, levette analogiche e tasti della tastiera restano quelli del `retroarch.cfg`.
Aggiunge poi le preferenze di P1 (per un ospite quelle predefinite): `input_rumble_gain`; con Filtro CRT e `paths.crt_shader` lo shader passa con `--set-shader`.
Aggiunge anche le chiavi di RetroArch della configurazione del gioco (grafica, latenza, audio, emulazione) e lo shader con `--set-shader`; le opzioni del core vanno invece nel suo `.opt` (API.md, «Configurazione dei giochi»). Per le TV che tagliano i bordi, nella Grafica di un gioco c'è il «Margine per la TV»: rimpicciolisce l'immagine al centro dello schermo di una percentuale per lato.
Imposta la cartella dei BIOS: `system_directory` (assoluta) e `systemfiles_in_content_dir = "false"`, così i core cercano i BIOS nella cartella di sistema di RetroArch e non in quella del gioco (API.md, «BIOS»).
Prima di giocare, se al core del gioco manca un BIOS obbligatorio del suo `.info`, la dashboard lo dice: «Scegli il BIOS…» apre la pagina «BIOS» della console (chiusa la pagina, il gioco parte se il BIOS ora c'è), «Avvia comunque» non lo chiede più per quel gioco fino alla chiusura della dashboard.
Infine la cartella di sessione `pixel-arcade-session/`, accanto a `paths.appendconfig` perché RetroArch in snap possa scriverci: `savestate_directory` e `savefile_directory` puntano lì, senza sottocartelle (`sort_*` a `false`), con stato automatico all'uscita e all'avvio, miniature, `savestate_auto_index` e `content_runtime_log` a `false` e i comandi di rete (`network_cmd_enable`, `network_cmd_port = "55355"`).
Prima di ogni avvio di RetroArch la cartella si svuota e riceve il salvataggio interno del P1; all'uscita lo stato automatico diventa il «Riprendi» dei profili in partita e il salvataggio interno torna al P1. pcsx2 (PS2) non salva nella cartella di sessione ma nella cartella di sistema di RetroArch (`pcsx2/memcards/Mcd001.ps2` e `Mcd002.ps2`): prima di ogni avvio la dashboard ci mette le memory card del P1 (`<data-dir>/saves/<profilo>/system/pcsx2/`, una coppia per profilo per tutti i giochi PS2, e una per gli ospiti) e all'uscita le riporta al P1. Se il P1 non ne ha, le toglie e il core ne crea di nuove, già formattate. Con pcsx2 il «Riprendi» non si carica all'avvio, perché il core si chiude: va nello slot di lavoro e la dashboard lo carica con `LOAD_STATE` 5 s dopo che RetroArch risponde `PLAYING` (attesa massima 90 s). Se la partita finisce o riparte prima del caricamento, lo stato automatico è della partita ripartita dall'inizio e il «Riprendi» resta quello di prima.
Contro i giochi bloccati la dashboard salva uno stato periodico: ogni minuto, ogni 5 minuti per PS2 e N64, configurabile nella pagina «Configurazione» → Emulazione. Con la combinazione di emergenza (predefinita SELECT+R2, tenuta 2 s, oppure 1 s se usa il tasto dell'uscita dal gioco) il gioco si chiude senza salvare il «Riprendi». Se all'uscita lo schermo sembra bloccato, la dashboard chiede «Il gioco era bloccato?». In entrambi i casi si sceglie uno stato e la partita riparte da lì; se è bloccato anche quello, la combinazione riapre la scelta (API.md, «Salvataggi di soccorso»).

**Core del gioco.** Al primo avvio la dashboard prova i core della lista della console che dichiarano l'estensione del file, nell'ordine della lista:
- un core non installato viene scaricato dal buildbot libretro nella cartella dei core; sopra i 50 MB chiede conferma;
- un core fallisce se RetroArch esce entro `probe.window_seconds` (10 s) con un errore, se nel log compare un errore di contenuto o di ROM mancanti, oppure se in quei secondi il core chiude il gioco e RetroArch torna al suo menu. RetroArch viene chiuso e si passa al core successivo;
- un'uscita con START tenuto nei primi secondi lascia il core «in prova» e all'uscita compare la domanda qui sotto;
- il primo core che supera i controlli resta «in prova». Se la partita dura almeno 2 minuti (`probe.auto_confirm_seconds`) il core è confermato da solo, altrimenti all'uscita compare «Il gioco ha funzionato con …?»: Sì lo conferma, No prova subito il core successivo;
- un gioco già lanciato riprende dal primo core non ancora provato, anche dopo un riavvio o se la lista è cambiata;
- se nessun core funziona, il gioco è segnato ⊘ «Incompatibile»; A propone «Riprova la ricerca».

A su un gioco della griglia porta a **Gioca**; ← → passano a **Descrizione**, **Trofei** e **Altro**, B torna alla griglia. «Altro» apre un menu con **Core: …**, **Comandi**, **Configura** e **Playlist**; con nessun core compatibile «Altro» mostra ⊘.

**Libreria più leggera.** La griglia mostra per ogni gioco solo copertina e titolo, più la coppa dorata se il gioco è compatibile con RetroAchievements e i pallini dei preferiti; anno, genere, regione e la coppa barrata stanno nella sezione in alto, accanto al nome della console. La scheda del gioco è a tre colonne senza riquadri e i valori lunghi vanno su due righe. La barra dei comandi della libreria mostra solo Apri, Filtri, Preferito (con dei giocatori), Console, Lettera, Giocatori e Profilo o Impostazioni. Il menu del core offre «Ricerca automatica al prossimo avvio» (azzera i tentativi del gioco) e la scelta a mano di un core compatibile, scaricato al prossimo avvio se manca.

Nella schermata di avvio e di gioco B due volte (entro 3 s) interrompe: durante la ricerca il core in prova non viene giudicato.
In gioco l'uscita (START tenuto 2 secondi, se non è cambiata) chiude RetroArch e si torna alla libreria, che ignora i tasti finché non vengono rilasciati; una notifica riporta la durata della partita.
Se il core chiude il gioco da solo e RetroArch torna al suo menu, la dashboard chiude RetroArch (entro circa un secondo, poi lo termina forzatamente).

Nella barra comandi i tasti frontali del joypad sono indicati dalla posizione in un rombo di quattro pallini (sotto = conferma, destra = indietro, sopra = preferito, sinistra = cerca), non dalla lettera.
Anche i tasti delle spalle sono disegnati per posizione, in un'icona con la parte alta del joypad: pieni i dorsali davanti (LB/RB, L1/R1, L/R) oppure i grilletti dietro (LT/RT, L2/R2, ZL/ZR).

## Salvataggi condivisi

Un salvataggio condiviso è un salvataggio interno (batteria, memory card) di partenza, uguale per tutti i profili: per esempio un salvataggio di GameFAQs con tutto sbloccato. È l'estensione pubblica `shared-saves` (`backend/pixelarcade/addons/shared-saves/`, `frontend/src/addons/shared-saves/`).

- **All'avvio** di un gioco che ne ha, la modale dei salvataggi li mostra sotto «Riprendi», gli slot e «Nuova partita», nella riga «SALVATAGGI CONDIVISI», con titolo e descrizione. La modale si apre anche se i giocatori non hanno salvataggi del gioco, e anche per un ospite.
- **La partita** parte dall'inizio con una copia del salvataggio condiviso al posto del salvataggio interno del P1. A fine partita la copia si butta: il salvataggio condiviso non cambia mai e quello del P1 resta com'era.
- **«Riprendi» e slot** (SELECT+L2 in partita) si salvano come sempre nei profili e ricordano da quale salvataggio condiviso sono nati («Da «titolo»» sotto la voce). Ripresi, ripartono con una copia di quel salvataggio condiviso. Il «Riprendi» è uno per gioco: una partita con un salvataggio condiviso prende il posto di quello della partita normale. Se il salvataggio condiviso è stato eliminato, lo slot riparte senza salvataggio interno.
- Trofei, XP e statistiche valgono come in ogni partita.

**Impostazioni → Salvataggi** (le modifiche si salvano subito):
- «Cartella»: dove stanno i salvataggi condivisi; vuota è `<data-dir>/shared-saves` (`~/.config/pixel-arcade/shared-saves`). `~` e i percorsi relativi valgono come nei percorsi delle Configurazioni. Cambiandola, i salvataggi della cartella di prima restano dove sono.
- «＋ Aggiungi salvataggio»: console, gioco (si cerca con la tastiera a schermo), file, titolo e descrizione. Il file si sceglie col joypad nel selettore dei file del disco della console, lo stesso dei BIOS (al massimo 16 MB); nella cartella del salvataggio va una copia, l'originale resta dov'è.
- L'elenco dei salvataggi: A apre titolo, descrizione ed «Elimina». «Rileggi la cartella» rilegge quelli copiati a mano.

**Formati.** Per la PS2 una memory card `.ps2`, oppure un salvataggio esportato `.max`, `.psu`, `.cbs`, `.xps`, `.sps` o `.npo`, che la dashboard importa in una memory card nuova con [mymcplus](https://github.com/thestr4ng3r/mymcplus) (programma esterno, cercato nel `PATH` e in `<data-dir>/tools/mymcplus/bin/`). Per le altre console il salvataggio interno grezzo del core: `.sav`, `.mcr`, `.mcd` e `.mc` diventano `.srm`, le altre estensioni restano. Il salvataggio deve essere della stessa regione del gioco.

Installazione di mymcplus sulla console, una volta:

```bash
python3 -m venv ~/.config/pixel-arcade/tools/mymcplus
~/.config/pixel-arcade/tools/mymcplus/bin/pip install mymcplus
```

**A mano.** Ogni salvataggio è una cartella `<cartella>/<console>/<id del gioco>/<nome>/`, dove `<id del gioco>` è il percorso del file dentro `games/<console>/` (per esempio `ps2/Tekken 5 (USA).iso/Tutto sbloccato/`). Dentro vanno i file del salvataggio, di cui conta solo l'estensione (`salvataggio.srm` diventa `<gioco>.srm`; per la PS2 la memory card si chiama `Mcd001.ps2`), le eventuali sottocartelle del core e, facoltativo, `info.json`:

```json
{
  "title": "Tutto sbloccato",
  "description": "Tutti i personaggi, Devil Within completato"
}
```

Senza `info.json` il titolo è il nome della cartella. Le cartelle vuote e quelle che iniziano con `.` non contano.

## Impostazioni

SELECT (F3, o il clic su «Impostazioni» nella barra comandi) apre le Impostazioni, con le sezioni Percorsi, Console, Joypad, RetroArch e Aspetto.
Le modifiche restano in una bozza finché non si sceglie «Salva»; B (Esc), SELECT o «Annulla» tornano alla libreria.
Con modifiche non salvate si apre prima una finestra con tre scelte (← → per scegliere, A per confermare):
«Annulla» (anche B) resta nelle Impostazioni, «Scarta modifiche» (rosso) esce senza salvare, «Salva modifiche» (verde, evidenziata all'apertura) salva ed esce.
Se il salvataggio non riesce si resta nelle Impostazioni e l'errore compare in una notifica e in fondo alla pagina.

| Joypad | Tastiera | Mouse | Azione |
| --- | --- | --- | --- |
| Croce o stick | Frecce | Passaggio del mouse; rotellina per scorrere | Sposta la selezione |
| A | Invio o Spazio | Clic | Modifica il campo (tastiera a schermo), apre il menu, esegue il pulsante |
| X | Canc | Pulsante ✕ della riga | Nella finestra di una console, toglie il core selezionato dalla lista |
| B o SELECT | Esc o F3 | Clic su «Indietro» nella barra comandi | Chiude la finestra della console, oppure torna alla libreria |

**Console.** La sezione elenca le cartelle di `games/` divise per marca, come la scheda TUTTE: le frecce scelgono la marca, A ci entra, B torna alle marche. Dentro, una riga per console (logo, giochi, «Pronta», numero di core, interruttore); A apre la finestra della console con la sua lista di core e le estensioni, B la chiude. Subito sotto l'elenco c'è «Elimina core inutilizzati».
L'interruttore «Accesa / Spenta» decide se la console è nella riga delle schede di tutti (senza scelta: accesa se ha giochi): si cambia con X (tastiera `/`, legenda «Accendi/spegni») e si salva con «Salva», come il resto delle Impostazioni. Le scelte dei profili valgono sopra l'interruttore (vedi «Riga delle console e scheda TUTTE»).
In fondo, nel gruppo ESTENSIONI, ci sono le console delle estensioni con impostazioni proprie, con il loro logo se ce l'hanno.
Per ogni cartella c'è una lista di core, provati nell'ordine mostrato all'avvio dei giochi (sprint 05).
- **Ordine**: automatico. Prima i core compatibili con RetroAchievements della console, installati o scaricabili, nell'ordine consigliato dalla [documentazione di RetroAchievements](https://docs.retroachievements.org/general/emulator-support-and-issues.html) (elenco in `backend/pixelarcade/ra_cores.py`); poi gli altri core installati in ordine alfabetico, gli altri scaricabili in ordine alfabetico e infine quelli non disponibili. Così il primo core provato, e scaricato se manca, è quello che attiva i trofei.
- **Stato dei core**: ogni core è segnato «installato», «da scaricare» (dal buildbot libretro, sprint 05) o «non disponibile».
- **Lista predefinita**: una cartella riconosciuta mai modificata parte dai core della sua tipologia (per esempio «Arcade» o «Nintendo - Nintendo Entertainment System»). Comprende anche i core compatibili con RetroAchievements disponibili. Sul Mega Drive i file `.32x` vanno a PicoDrive, perché Genesis Plus GX non dichiara quell'estensione. Resta segnata «predefinita» e segue i core disponibili del momento.
- **Modifiche**:
  - «Aggiungi da tipologia…» aggiunge tutti i core di una o più tipologie, ricavate dai file `.info` dei core di RetroArch;
  - «Aggiungi core…» aggiunge core singoli;
  - A su un core apre «Togli dalla lista»; X, Canc o ✕ lo tolgono subito.
- **Pronta**: la console è pronta se almeno un core della lista è installato o scaricabile.
- **Estensioni**: vuote valgono quelle predefinite del sistema oppure, per le cartelle non riconosciute, quelle dei core della lista, mostrate come suggerimento.
- **BIOS…**: pagina dei file di sistema dei core della console (anche dalla riga «BIOS» nell'Emulazione di «Configurazione…»). Per ogni core: i file del suo `.info` con «Obbligatorio» o «Facoltativo» e lo stato («Presente ✓» con il checksum giusto, «Presente», «Versione diversa», «Mancante»), quelli indicati dalle sue opzioni e quelli aggiunti a mano. A su un file apre il selettore dei file: il file scelto si copia nella cartella dei BIOS con il nome giusto (con una conferma se c'è già; con una versione diversa da quella attesa si copia lo stesso, con un avviso). «＋ Aggiungi un BIOS…» c'è per ogni core, anche se non ne dichiara: dopo il file si sceglie la cartella (quella dei BIOS, una sua sottocartella o una nuova) e il nome. X (Canc) toglie un file copiato dalla dashboard, B chiude. Aggiungendo alla lista un core a cui manca un BIOS obbligatorio compare un avviso.

Il selettore dei file legge il disco senza modificarlo:

Più file insieme si scelgono per una cartella in cui va un file di nome qualsiasi (per esempio `pcsx2/bios`) e per «＋ Aggiungi un BIOS…»; si possono spuntare anche file di cartelle diverse e si copiano con il loro nome. Se alcuni ci sono già, una sola conferma li sostituisce tutti. La volta dopo il selettore riparte dall'ultima cartella aperta.

I due menu «Aggiungi…» hanno ricerca e selezione multipla:

Le spunte restano quando cambia il testo della ricerca, e non c'è un limite al numero di voci.
- **Joypad**: «Impara tasti» chiede un tasto alla volta (Conferma, Indietro, Cerca, Preferito, spalle, SELECT, START). I tasti già usati e la croce vengono rifiutati. Per annullare senza modifiche: tenere premuto per 1,5 s il tasto Indietro attuale, oppure Esc o il pulsante «Annulla». I nuovi tasti valgono dopo «Salva». Questi tasti servono solo nei menu della dashboard.
  «Uscita dal gioco» sceglie come si chiude RetroArch: «Tieni premuto START (2 s)» (predefinita), «Tieni premuto SELECT (2 s)» o «START+SELECT», che in molti giochi PS1 è anche il reset. Vale dalla partita dopo «Salva». La combinazione di emergenza può usare il tasto da tenere: in quel caso scatta dopo 1 secondo invece di 2, prima che RetroArch esca da solo salvando il «Riprendi». Un gioco o una console possono avere un'uscita diversa: «Altro» → «Configura» → Emulazione → «Uscita dal gioco»; senza scelta vale questa.
- **Joypad nei giochi**: elenca i joypad come li vede RetroArch, con «Configurato» o «Non configurato», e per ognuno «Configura» o «Riconfigura». La configurazione chiede i tasti uno alla volta (tasto in basso, a destra, a sinistra, in alto, dorsali, grilletti, L3, R3, SELECT, START e croce), poi scrive l'autoconfig di RetroArch e apre la prova dei tasti, che si chiude con START. I tasti facoltativi si saltano ripremendo il tasto in basso. «Ripristina tasti di RetroArch» toglie dal `retroarch.cfg` i tasti dei giocatori 1 e 2, che altrimenti avrebbero la precedenza sugli autoconfig. La configurazione funziona solo con il driver `sdl2` di RetroArch (`API.md`, «Joypad in RetroArch»).
- **Elimina core inutilizzati** (sotto l'elenco delle console): elenca i core scaricati dalla dashboard che nessun gioco usa (né confermati né in prova), con lo spazio occupato, e li cancella dopo la conferma; i core installati da RetroArch non compaiono mai.
- **RetroArch**: numero e data dell'elenco dei core scaricabili, con «Aggiorna elenco core». Al primo avvio l'elenco si scarica da solo; senza rete restano disponibili solo i core installati. Sotto c'è lo stato della combinazione d'uscita col joypad.
- **Prestazioni** (nella scheda Configurazioni, sotto RetroArch): «Processore al massimo durante le partite», Sì (predefinito) o No; A lo cambia. La nota dice il governor in uso, oppure che lo script di sistema non è installato (vedi «Processore al massimo»).
- **Aspetto**: «Tema grafico» sceglie lo sfondo della dashboard: «Casuale a ogni avvio» (predefinito) oppure uno fisso. I temi sono otto: Salotto 8 bit, Portatile verde, 16 bit, Era 32 bit, Primi 3D, Home computer, Sala giochi anni '80, Anni 2000. Ognuno dà una luce colorata allo sfondo, un disegno sfumato in basso e alcuni sprite in stile pixel art che galleggiano piano nei margini, trasparenti e dietro al contenuto. Il tema scelto si vede subito e si salva con «Salva». Sul telefono resta solo la luce; con la riduzione del movimento del sistema gli sprite stanno fermi. «Salvaschermo» sceglie dopo quanto tempo senza comandi parte (predefinito 2 minuti, oppure «Mai»; vedi «Salvaschermo» sopra). «Contenuto del salvaschermo» sceglie tra «Misto» (predefinito), «Copertine» e «Partite» (vedi «Partite nel salvaschermo» sopra). «Pubblicità dei tornei» (sì di predefinito) fa del salvaschermo il manifesto dei tornei di oggi (vedi «Tornei nel salvaschermo» sopra). «Uscita dei profili» sceglie dopo quanto tempo senza comandi escono tutti i profili e torna «PRESS START» (predefinito 1 minuto, oppure «Mai»). Nel pannello Suoni, «Suoni» (Sì, predefinito, o No) accende o spegne tutto; «Volume effetti» (predefinito 75%) e «Volume musica» (predefinito 50%) vanno da «Spento» a 100%. Si sentono subito e si salvano con «Salva». Sotto c'è il pannello «Wrapped di casa» (vedi «Wrapped» sopra).
- Durante una partita le Impostazioni non si possono salvare.
- **Aggiorna libreria** rilegge cartelle e giochi dal disco, mantenendo le modifiche non salvate.
- Un valore non valido (per esempio una cartella dei giochi inesistente) mostra l'errore sopra «Salva» e non salva nulla.

Chrome vede un joypad solo dopo la pressione di un suo tasto: fino ad allora la barra comandi mostra «Premi un tasto del joypad».

## RetroAchievements

[RetroAchievements](https://retroachievements.org) aggiunge trofei ai giochi retro; RetroArch li controlla durante la partita e li registra sull'account collegato. Serve Internet sulla console.

- **Chiave Web API** (Impostazioni → Configurazioni → RetroAchievements): una sola per tutta la dashboard, da retroachievements.org → Impostazioni → Keys. Si scrive con la tastiera a schermo o si incolla (Ctrl+V o pulsante «Incolla»); prima di salvarla la dashboard la prova. Dopo il salvataggio se ne vedono solo gli ultimi 4 caratteri.
- **Account del profilo** (pagina profilo → Trofei → «Collega account»): nome utente e password, con la tastiera a schermo o quella fisica. La password compare come pallini (MOSTRA la rivela) e serve solo a ottenere il token: non viene salvata. «Scollega» cancella il token.
- **Tastiera a schermo**: `#+=` apre la pagina dei simboli (tutti i caratteri ASCII stampabili), `ABC` torna alle lettere. Ctrl+V o il pulsante «Incolla» in alto a destra (mouse) incollano nel campo aperto; la prima volta il pulsante fa chiedere a Chrome il permesso di leggere gli appunti.
- **In partita** RetroArch accede con l'account di chi è P1 all'avvio (scritto nella schermata di avvio: «Trofei RetroAchievements a …»). Un cambio di P1 vale dalla partita successiva. La modalità hardcore è sempre spenta, perché con l'hardcore gli stati di salvataggio, e quindi «Riprendi», non funzionano.
- **Due giocatori**: RetroArch accetta un solo account, quindi sul sito i trofei vanno al P1. La dashboard li registra anche nel profilo del P2, segnati «in coppia con …».
- **Scheda del gioco**: il pulsante «Trofei» (accanto a «Descrizione») mostra i trofei del gioco con quelli già sbloccati dal P1; ↑↓ scorrono l'elenco, A torna alla scheda. Le console a cartuccia e l'arcade si riconoscono subito dall'hash del file; i giochi su disco (PS1 e simili) e gli archivi `7z` dopo la prima partita. Un file non riconosciuto o una versione non supportata dal sito lo dicono nella scheda.
- **Profilo**: punti, rank e ultimi trofei dal sito, più i trofei vinti in coppia.
- **Core**: nell'ordine automatico vengono prima i core compatibili con RetroAchievements (vedi «Ordine» nelle Impostazioni). Con altri core il gioco parte, ma i trofei possono restare inattivi.

## Dati

Tutto lo stato sta in un solo database SQLite: `~/.config/pixel-arcade/pixel-arcade.db`.
Nella stessa cartella c'è `chrome-profile/`, il profilo usato dal Chrome della dashboard.
Le impostazioni (tabella `settings`) partono dai valori predefiniti di `backend/pixelarcade/config.py`.
Le console hanno estensioni e lista dei core nelle tabelle `systems` e `system_cores`; l'elenco dei core scaricabili sta in `buildbot_cores`, i core scaricati dalla dashboard in `downloaded_cores`.
Il core di ogni gioco sta in `game_cores`, i core provati (con esito e ultime righe del log di RetroArch) in `core_attempts`, le partite in `sessions`.
Il gioco della sfida di ogni settimana sta in `weekly_challenges` (data del lunedì, console, gioco).
Le console accese o spente per tutti dalle Impostazioni stanno in `console_settings`; le console accese o spente da ogni profilo nella propria riga in `account_consoles` (con `ON DELETE CASCADE`: le righe di un profilo se ne vanno con lui).
RetroAchievements: account dei profili (nome utente e token) in `ra_accounts`, gioco riconosciuto di ogni file in `ra_games`, trofei delle partite in `ra_unlocks`; la chiave Web API è la riga interna `retroachievements.api_key` di `settings`. Gli elenchi dei giochi con gli hash e i badge stanno in cache in `~/.config/pixel-arcade/retroachievements/`.
Le migrazioni in `backend/pixelarcade/db/migrations/` vengono applicate all'avvio, una sola volta ciascuna.

## Sviluppo

1. Backend con una cartella dati di prova, senza Chrome:

   ```bash
   bash run_dashboard.sh --no-browser --data-dir /tmp/pixel-arcade-prova
   ```

2. In un altro terminale, il server di sviluppo di Vite (inoltra `/api` al backend sulla porta 8765):

   ```bash
   cd dashboard/frontend
   npm run dev
   ```

Il backend richiede comunque una build in `frontend/dist` per partire.
